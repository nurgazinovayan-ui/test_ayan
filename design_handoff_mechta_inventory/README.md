# Handoff: Mechta Marketing Inventory 2026 — посадочная с категориями + бриф-квиз

## Overview
Посадочная страница для вендоров Mechta.kz: систематизированный маркетинговый инвентарь 2026 (9 категорий, 44 инструмента), переключение категорий табами, поиск, фильтр по бизнес-задаче, выбор услуг в корзину и многошаговый бриф-квиз, который формирует готовый текст заявки и отправляет его на webhook Make.com.

## About the Design Files
Файлы в этом пакете — **дизайн-референсы, сделанные на HTML**. Это прототип, показывающий целевой внешний вид и поведение, а не продакшн-код для копирования.

Задача: **воспроизвести эти дизайны в существующей среде целевого проекта** (React / Next.js / Vue / и т.д.), используя её принятые паттерны, библиотеки и систему компонентов. Если среды ещё нет — выбрать подходящий фреймворк (рекомендация: Next.js + TypeScript + Tailwind) и реализовать дизайн в нём.

Прототип написан в собственном шаблонном рантайме (`support.js`, класс `Component extends DCLogic`, теги `<sc-for>` / `<sc-if>`). **Не портируйте рантайм** — переносите разметку, стили и логику состояния.

## Fidelity
**High-fidelity.** Финальные цвета, типографика, отступы, состояния и интерактив. Воспроизводить пиксель-в-пиксель средствами целевого стека.

## Interactions & Behavior

| Действие | Поведение |
|---|---|
| Клик по табу | `cat = id`; если текущая задача отсутствует в категории — `goal = 'all'` |
| Ввод в поиск | `q`; при непустом `q` игнорируется активная категория, ищем по всем |
| Клик по чипу задачи | `goal = id` |
| Клик «Выбрать» | тоггл названия инструмента в массиве `picked`; сбрасывает `listCopied` |
| Клик «Далее» | `step + 1`; на последнем шаге — `briefDone = true` |
| Клик «←» | `step − 1` (не ниже 0) |
| Клик «Скопировать бриф» | снимает `readonly`, выделяет весь текст, `document.execCommand('copy')`, возвращает `readonly`; fallback — Clipboard API. Подпись «Скопировано ✓» на 2 с |
| Клик «Отправить бриф» | POST JSON на Web3Forms (+ на вебхук, если задан); «Отправляем…» → «Отправлено ✓». Если ключ не задан или письмо не ушло — текст брифа копируется в буфер, открывается `mailto:`, подпись «Открыли письмо ✓» |
| Клик по кнопке с адресом | Clipboard API с fallback на скрытую textarea + `execCommand`; тост + пружинка на 2 с |
| Клик «Заполнить бриф ↓» | якорный переход к `#brief` |

**Почему execCommand:** страница встраивается в Tilda через iframe, где Clipboard API часто блокируется разрешениями. В целевом проекте, если страница не в iframe, достаточно `navigator.clipboard.writeText`.

## State Management
```js
{
  cat: 'audience',      // активная категория
  goal: 'all',          // фильтр по бизнес-задаче
  q: '',                // поисковый запрос
  picked: [],           // названия выбранных инструментов
  step: 0,              // текущий шаг брифа (0..7)
  brief: {},            // ответы брифа по id поля
  briefDone: false,     // показан экран результата
  copied: false,        // тост копирования адреса
  listCopied: false,    // подтверждение копирования списка услуг
  briefCopied: false,   // подтверждение копирования брифа
  sending: false, sent: false, mailed: false, sendError: ''   // отправка брифа
}
```
Производные значения (счётчики табов, доступные задачи, тексты) считаются из состояния при рендере, не хранятся.

## Размещение и вставка в Тильду

В блок T123 идёт **только iframe-сниппет** из `tilda-embed-iframe.txt` (~1 КБ). Сам `Mechta Inventory 2026.html` в блок вставить нельзя: лимит T123 — около 100 000 байт, файл — 264 КБ, Тильда ответит «слишком много контента в блоке».

### Где разместить файл
Тильда не хранит произвольные `.html` — своего файлового хостинга под это у неё нет (прежняя инструкция «загрузите в файлы Тильды» была неверной).

| Вариант | Как |
|---|---|
| **Netlify Drop** | перетащить файл на [app.netlify.com/drop](https://app.netlify.com/drop) — ссылка сразу, без аккаунта и гита |
| **GitHub Pages** | файл уже лежит в `docs/index.html`; включить *Settings → Pages → Source: main, папка /docs* |
| Свой хостинг / S3 / Cloudflare Pages | как обычный статический файл |

Google Drive и Яндекс.Диск **не подойдут**: публичная ссылка отдаёт файл на скачивание или страницу-просмотрщик, а не сам HTML — в iframe это не работает.

### Автоподстройка высоты
Страница сообщает свою высоту родителю через `postMessage` (`{ __mechtaHeight: <px> }`), сниппет её слушает и выставляет высоту iframe. Читать `contentDocument`, как делал прежний сниппет, нельзя: файл лежит на другом домене, и браузер запретит доступ — высота молча застывала на `min-height: 1200px`.

Высота считается по низу самого нижнего блока внутри `#dc-root > .sc-host`, а не по `documentElement.scrollHeight`: рантайм ставит `html,body,#dc-root{height:100%}` (`FULL_PAGE_CSS` в `support.js`), из-за чего `scrollHeight` не может стать меньше высоты iframe — блок рос и не сжимался обратно при поиске или смене категории.

### Две особенности автономной сборки
- **`window.__resources = {}` обязателен.** Без него `support.js` (строка ~158) до-загружает собственный URL ещё раз и перезаписывает шаблон результатом разбора — механика hot-reload редактора. По `file://` запрос рубит CORS и страница работает случайно, а по `http(s)`, то есть на любом реальном хостинге, fetch удаётся, разбор инлайненного файла даёт пустой шаблон и **страница рендерится пустой**. Пустой объект это отключает и безопасен: все обращения к `__resources` в рантайме — `res ? res[url] : undefined`.
- **Копирование в буфер идёт через `execCommand`**, а не через `navigator.clipboard`. В iframe объект `clipboard` существует, но `writeText` отклоняется permissions policy: получался unhandled rejection, а подпись «Скопировано ✓» появлялась, хотя ничего не скопировалось. Сниппет дополнительно отдаёт iframe `allow="clipboard-write"`.

## Отправка брифа (интеграция)

Почта mechta.kz **на Яндексе**, а он жёстко фильтрует письма от сторонних отправителей. Web3Forms возвращал `success: true`, но письма не доходили — именно этот случай. Поэтому письмо должно уходить **через SMTP самой Яндекс-почты**: тогда для Яндекса отправитель свой, а не внешний сервис.

Браузер по SMTP ходить не умеет, нужен релей. Отсюда схема:

```
страница → вебхук Make.com → Email-модуль по SMTP Яндекса → ящик
```

### Настройка
1. В Make.com создать сценарий: **Webhooks → Custom webhook**, скопировать URL.
2. Вторым шагом **Email → Send an email** с подключением по своему SMTP:

   | Параметр | Значение |
   |---|---|
   | Сервер | `smtp.yandex.ru` |
   | Порт | 465, SSL (587 — если клиент начинает без шифрования) |
   | Логин | полный адрес ящика |
   | Пароль | **пароль приложения** из Яндекс ID — 16 символов без пробелов |

   Логин — именно полный адрес (`user@mechta.kz`), не часть до «@».

   И перед этим в самой Яндекс-почте надо **включить доступ для почтовых программ**: *Настройки → Все настройки → Почтовые программы → разрешить IMAP*. Без этого SMTP отвечает `535 5.7.8 authentication failed` даже с верным паролем приложения. В Яндекс 360 доступ может быть закрыт политикой организации — тогда включает администратор.

   В теле письма использовать поле `brief_text`, в Reply-To — `contact_email`.
3. Вставить URL вебхука в `webhookUrl` в `window.MECHTA_CONFIG`.
4. Проверить связку через `tools/send-test.html` до правки лендинга.

### Если SMTP отвечает 535 5.7.8
Соединение установлено, отказ только на авторизации — сервер и порт верные. Дальше смотреть на текст после кода, он означает разные вещи:

**`Invalid user or password`** — не подошли учётные данные:
1. использован пароль аккаунта вместо пароля приложения;
2. пароль приложения вставлен с пробелами (показывается блоками по 4 символа);
3. логин указан без домена;
4. ящик создан, но в веб-интерфейс под ним ни разу не входили и условия не приняли.

**`This user does not have access rights to this service`** — пароль принят, но ящику **запрещён доступ по протоколам**. Это уже не аутентификация, а права:
1. в самой почте: *Настройки → Все настройки → Почтовые программы → разрешить IMAP*. Неочевидно, но этот переключатель открывает и SMTP тоже — они под одним разрешением;
2. если переключатель недоступен или не помогает — доступ закрыт политикой организации в Яндекс 360, и включить его может только администратор для конкретного сотрудника.

В тексте ошибки Яндекс отдаёт идентификатор запроса (вид `1791175015-taCEkhjk8W20`) — с ним их поддержка смотрит конкретную попытку входа.

Если администратор доступ не даёт, SMTP Яндекса отпадает. Схема при этом не меняется: в Make вместо модуля Email подключается **Gmail по OAuth** — пароля нет вообще, только разрешение в браузере. Письмо уходит с Google-адреса, но это легитимный отправитель, не притворяющийся доменом mechta.kz, поэтому антиспуфинг Яндекса его не режет.

### Каналы и приоритет
Каналы пробуются по очереди, **первый успешный решает исход** — повторной отправки не происходит.

| № | Канал | Роль |
|---|---|---|
| 1 | `webhookUrl` (Make.com → SMTP Яндекса) | основной: письмо уходит от своего же домена |
| 2 | `web3formsKey` | запас, если вебхука нет. На Яндекс может не дойти |
| 3 | `mailto:` | последний рубеж: ничего не настроено или всё упало |

«Отправлено ✓» ставит только канал, который реально доставляет письмо. Три исхода:

| Исход | Подпись кнопки |
|---|---|
| канал сработал | «Отправлено ✓» |
| ничего не настроено | «Открыли письмо ✓» |
| все каналы упали | «Открыли письмо ✓» + сообщение об ошибке |

Тело `mailto` режется до 1600 символов — лимит в Windows/Outlook около 2000, длинный бриф приезжал обрубленным. Полный текст копируется в буфер.

### Тело запроса
Все поля брифа по их `id`, плюс `services` (выбранные инструменты через «; »), `brief_text` (готовый текст), `subject`, `Name` (ответственный), `formservices`.

Для Web3Forms дополнительно `access_key`, `from_name` и `email` (Reply-To) — последний **только если вендор заполнил «Email для связи»**. Адрес получателя туда ставить нельзя: письмо на свой же домен от стороннего сервера антиспуфинг считает подделкой. Служебные поля собираются **поверх** полей брифа, иначе одноимённый `id` вопроса перетёр бы `access_key` или `subject`.

### Чего пробовать не стоит
- **Другой сервис форм** (Formspree, FormSubmit, EmailJS) — тот же сторонний отправитель, та же фильтрация у Яндекса.
- **Форма Тильды** — при вставке через iframe `tilda-forms.js` недоступен: он живёт в родительском документе. Нужна либо инлайн-вставка, либо мост `postMessage`.
