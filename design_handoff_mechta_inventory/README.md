# Handoff: Mechta Marketing Inventory 2026 — посадочная с категориями + бриф-квиз

## Overview
Посадочная страница для вендоров Mechta.kz: систематизированный маркетинговый инвентарь 2026 (9 категорий, 44 инструмента), переключение категорий табами, поиск, фильтр по бизнес-задаче, выбор услуг в корзину и многошаговый бриф-квиз, который формирует готовый текст заявки и отправляет его на webhook Make.com.

## About the Design Files
Файлы в этом пакете — **дизайн-референсы, сделанные на HTML**. Это прототип, показывающий целевой внешний вид и поведение, а не продакшн-код для копирования.

Задача: **воспроизвести эти дизайны в существующей среде целевого проекта** (React / Next.js / Vue / и т.д.), используя её принятые паттерны, библиотеки и систему компонентов. Если среды ещё нет — выбрать подходящий фреймворк (рекомендация: Next.js + TypeScript + Tailwind) и реализовать дизайн в нём.

Прототип написан в собственном шаблонном рантайме (`support.js`, класс `Component extends DCLogic`, теги `<sc-for>` / `<sc-if>`). **Не портируйте рантайм** — переносите разметку, стили и логику состояния.

## Fidelity

## Interactions & Behavior

| Действие | Поведение |
|---|---|
| Клик по табу | `cat = id`; если текущая задача отсутствует в категории — `goal = 'all'` |
| Ввод в поиск | `q`; при непустом `q` игнорируется активная категория, ищем по всем |
| Клик по чипу задачи | `goal = id` |
| Клик «Выбрать» | тоггл названия инструмента в массиве `picked`; сбрасывает `listCopied` |
| Клик «Далее» | `step + 1`; на последнем шаге — `briefDone = true` |
| Клик «←» | `step − 1` (не ниже 0) |
| Клик «Скопировать бриф» | снимает `readonly`, выделяет весь текст, `document.execCommand('copy')`, возвращает `readonly`; fallback — Clipboard API. Подпись «Скопировано ✓» на 2 с |
| Клик «Отправить бриф» | POST JSON на Web3Forms (+ на вебхук, если задан); «Отправляем…» → «Отправлено ✓». Если ключ не задан или письмо не ушло — текст брифа копируется в буфер, открывается `mailto:`, подпись «Открыли письмо ✓» |
| Клик по кнопке с адресом | Clipboard API с fallback на скрытую textarea + `execCommand`; тост + пружинка на 2 с |
| Клик «Заполнить бриф ↓» | якорный переход к `#brief` |

**Почему execCommand:** страница встраивается в Tilda через iframe, где Clipboard API часто блокируется разрешениями. В целевом проекте, если страница не в iframe, достаточно `navigator.clipboard.writeText`.

## State Management
```js
{
  cat: 'audience',      // активная категория
  goal: 'all',          // фильтр по бизнес-задаче
  q: '',                // поисковый запрос
  picked: [],           // названия выбранных инструментов
  step: 0,              // текущий шаг брифа (0..7)
  brief: {},            // ответы брифа по id поля
  briefDone: false,     // показан экран результата
  copied: false,        // тост копирования адреса
  listCopied: false,    // подтверждение копирования списка услуг
  briefCopied: false,   // подтверждение копирования брифа
  sending: false, sent: false, mailed: false, sendError: ''   // отправка брифа
}
```
Производные значения (счётчики табов, доступные задачи, тексты) считаются из состояния при рендере, не хранятся.

## Отправка брифа (интеграция)

Основной канал — **Web3Forms**: письмо с брифом уходит на почту без своего бэкенда и работает из iframe-вставки в Тильде.

### Настройка (2 минуты)
1. На [web3forms.com](https://web3forms.com) указать почту → на неё придёт **Access Key** (адрес подтверждается по ссылке из письма).
2. Открыть `Mechta Inventory 2026.html`, в блоке `window.MECHTA_CONFIG` в самом начале файла вставить ключ в `web3formsKey`.
3. Загрузить файл в Тильду (*Настройки сайта → Файлы*) и вставить iframe из `tilda-embed-iframe.txt` в блок T123.

```js
window.MECHTA_CONFIG = {
  web3formsKey: 'xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx',
  emailTo: 'aidyn.argyn@mechta.kz',
  webhookUrl: ''
};
```

Конфиг читается из `window.MECHTA_CONFIG`, при его отсутствии — из props (секция «Отправка брифа» в DC-редакторе): `web3formsKey`, `emailTo`, `webhookUrl`. Ключ вынесен в начало файла намеренно: править его внутри HTML-экранированного `data-props` в середине 260-килобайтного файла неудобно.

| Канал | Роль |
|---|---|
| **Web3Forms** | `POST https://api.web3forms.com/submit`. Основной: только он решает, считать бриф отправленным |
| **Вебхук** (`webhookUrl`) | Побочный, best-effort: пишет заявку в Make.com / CRM. Его падение не меняет статус |
| **`mailto:`** | Фоллбэк: ключ не задан либо письмо не ушло |

Статус кнопки различает три исхода, и это важно: «Отправлено ✓» означает именно «письмо ушло автоматически».

| Исход | Подпись | Дополнительно |
|---|---|---|
| Web3Forms ответил `success: true` | «Отправлено ✓» | — |
| Ключ не задан | «Открыли письмо ✓» | открыт `mailto`, полный текст в буфере |
| Письмо не ушло (4xx, сеть, `success: false`) | «Открыли письмо ✓» | сообщение об ошибке + `mailto` + буфер |

`success: false` при HTTP 200 (исчерпанный лимит, неподтверждённый ключ) обрабатывается как отказ — иначе кнопка врала бы об отправке.

Тело письма в `mailto` режется до 1600 символов: лимит mailto в Windows/Outlook — около 2000, и длинный бриф приезжал обрубленным. Полный текст при этом копируется в буфер обмена.

### Тело запроса
Все поля брифа по их `id`, плюс:
- `services` — выбранные инструменты через «; »
- `brief_text` — готовый текст брифа целиком
- `subject` — «Бриф кампании — Mechta Inventory 2026: <кампания>»
- `Name` — значение поля «Ответственный»
- `formservices` — `"Mechta Inventory 2026"`

Для Web3Forms дополнительно: `access_key`, `from_name`, `email` (Reply-To).

### Почему не форма Тильды
В прототипе была заготовка под тильдовский приёмник — скрытая форма `js-form-proccess`. При вставке через iframe она нерабочая: `tilda-forms.js` и сервисы приёма данных живут в родительском документе, а iframe его скриптов не видит. Форма удалена как мёртвый код. Чтобы использовать приёмник Тильды, нужен либо инлайн-вставка вместо iframe, либо мост `postMessage` из iframe в родительскую страницу.

### Куда двигаться на продакшене
Серверный роут (например, Next.js route handler + Resend / SMTP): скрывает ключ, снимает зависимость от сторонних лимитов, позволяет добавить антиспам, логирование и HTML-вёрстку письма. Тогда `web3formsKey` оставить пустым, а `webhookUrl` направить на свой эндпоинт — либо заменить вызов напрямую.

Любой сторонний приёмник должен отдавать `Access-Control-Allow-Origin`, иначе браузер заблокирует запрос (у Web3Forms заголовок настроен).

## Рекомендации по реализации
1. Данные (`CATS`, `TOOLS`, `STEPS`) — в отдельные модули или CMS; UI читает их как пропсы.
2. Состояние фильтров (`cat`, `goal`, `q`) стоит держать в URL-параметрах — даёт шеринг ссылок на категорию.
3. Выбранные услуги имеет смысл персистить в `localStorage`.
4. Бриф — валидация обязательных полей (сейчас её нет, можно пройти шаги пустыми).
5. Отправку перевести на серверный роут (скрыть URL webhook, обойти CORS, добавить антиспам).
6. Проверить мобильную раскладку: сетка карточек уже адаптивна, но тёмная секция (`padding: 72px 64px`) и бриф (`40px 44px`) требуют уменьшенных отступов на узких экранах.
